# Resume API

A public HTTP API that turns resume data into a print-ready A4 PDF, plus a
dependency-free browser connector that lets any website collect resume details
and hand the visitor a finished document.

Two dependencies: `express` and `jspdf`. No headless browser, no external
rendering service, no database.

```
JSON in  ──►  POST /v1/resumes/pdf  ──►  PDF out
```

## Quick start

```bash
npm install
npm start
```

Then open <http://localhost:3000> for the docs and live playground.

```bash
npm test     # 16 end-to-end tests against a real listener
```

Configuration is optional; copy `.env.example` to `.env` to change anything.

| Variable | Default | Meaning |
| --- | --- | --- |
| `PORT` | `3000` | Listening port |
| `RESUME_API_KEYS` | *(empty)* | Comma separated keys. Empty means **open public mode** |
| `RESUME_CORS_ORIGINS` | `*` | Allowed browser origins |
| `RESUME_RATE_MAX` / `RESUME_RATE_WINDOW_MS` | `60` / `60000` | Per-IP rate limit |
| `RESUME_MAX_BODY` | `256kb` | Request body limit |
| `RESUME_DEFAULT_TEMPLATE` | `classic` | Template used when none is given |
| `RESUME_FOOTER_TEXT` | `Generated by Resume Builder` | Footer printed on every page |

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/health` | Liveness probe |
| `GET` | `/v1/templates` | Template catalogue (13 designs, 4 categories) |
| `GET` | `/v1/schema` | JSON Schema of the payload |
| `GET` | `/v1/openapi.json` | OpenAPI 3.0 description |
| `POST` | `/v1/validate` | Normalise and validate, no rendering |
| `POST` | `/v1/resumes/preview` | HTML preview (`?full=1` for a standalone page) |
| `POST` | `/v1/resumes/pdf` | The PDF (`?format=base64` for JSON) |

`/api/v1/...` is an alias of `/v1/...` for callers who expect that prefix.

### Generate a PDF

Any HTTP client works. The request is a JSON POST, the response is the PDF:

```
POST /v1/resumes/pdf
Content-Type: application/json

{
  "fullName": "Asha Rao",
  "email": "asha@example.com",
  "phone": "9876543210",
  "skills": "Python, SQL, Airflow",
  "template": "modern"
}
```

```
200 OK
Content-Type: application/pdf
Content-Disposition: attachment; filename="Asha_Rao_Resume.pdf"
```

From JavaScript:

```js
const res = await fetch('http://localhost:3000/v1/resumes/pdf', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ fullName: 'Asha Rao', email: 'asha@example.com', template: 'modern' })
});
const pdf = await res.blob();
```

Add `?format=base64` (or send `Accept: application/json`) to get
`{ pdf_base64, pages, bytes, filename }` instead of binary — useful from
environments that cannot handle raw bytes.

### Payload

Only `fullName` and `email` are required. Everything else is optional and is
left out of the document when empty. The API accepts the same field names the
Resume Builder form uses, plus common aliases, so an existing form usually maps
across without changes:

| Field | Type | Notes |
| --- | --- | --- |
| `fullName` | string | Required, up to 120 characters. Aliases: `name`, `full_name`. |
| `email` | string | Required, must look like an address. Aliases: `mail`, `emailAddress`. |
| `phone` | string | Digits, spaces, `+ ( ) -` only. Alias: `mobile`. |
| `address`, `linkedin`, `github`, `languages` | string | Printed in the contact block. |
| `summary` | string | Career objective. Aliases: `objective`, `about`. |
| `qualifications` | array | Up to 20 of `{degree, university, year, score, status}`. Alias: `education`. |
| `edu_12th_*`, `edu_10th_*` | string | School, board, stream, year, score. |
| `workExperience`, `projects`, `skills`, `certifications`, `actHob` | string or array | Arrays are joined with commas. |
| `template` | string | Any id from `/v1/templates`. |

Errors come back as `422` with a `details` array of `{ field, message }`, so a
connector can highlight the exact input that failed.

## Embed it on any website

`sdk/resume-builder-connect.js` is a dependency-free browser connector — no
build step, no framework, no cookies.

```html
<script src="resume-builder-connect.js"></script>
<div id="resume-widget"></div>
<script>
  const rb = ResumeBuilderConnect.init({
    baseUrl: 'https://your-api-host',
    apiKey: 'optional-if-the-server-requires-one'
  });

  // 1. A ready-made form that collects details and downloads the PDF
  rb.mount('#resume-widget', { template: 'modern' });

  // 2. Or drive it from your own UI
  await rb.downloadPDF({ fullName: 'Asha Rao', email: 'asha@example.com' });
</script>
```

The connector exposes `templates()`, `validate(data)`, `previewHTML(data)`,
`generatePDF(data)` (returns a Blob) and `downloadPDF(data)`.

Open `sdk/example.html` in a browser with the API running to see the widget in
action.

## Deploy

Any Node host works — Render, Railway, Fly, a VPS, or Docker:

```bash
docker build -t resume-api .
docker run -p 3000:3000 resume-api
```

For a serverless platform, point the handler at `createApp()` from
`src/app.js`; the app is a plain Express instance with no long-lived state
beyond the in-process rate-limit buckets.

## How it renders

`assets/js/templates.js` holds the 13 resume templates. Each template exposes
`preview(state)` — the on-screen HTML — and `draw(doc, state)`, which lays the
document out with jsPDF. The file is plain JavaScript with no DOM dependency,
so `src/resume-engine.js` evaluates it in a Node `vm` context and drives it with
the `jspdf` package directly. The result is a real, selectable-text PDF built by
the same layout code a browser uses, with no Chromium in the pipeline.

`assets/` is a copy of the renderer from the
[Professional Resume Builder](https://github.com/pandasuryanarayan/Professional-Resume-Builder)
site, which is the design source of truth. If a template changes there, re-copy
`js/templates.js` and `css/style.css` into `assets/` so the two stay in step.

## Project layout

```
src/
  index.js          process entry point
  app.js            express routes, OpenAPI document
  config.js         env parsing
  resume-engine.js  loads the renderer, produces PDFs and previews
  validate.js       normalisation, aliases, JSON Schema
  middleware.js     request id, CORS, API keys, rate limiting, errors
public/             docs page and live playground
sdk/                browser connector and example page
assets/             vendored template renderer and preview styles
test/               end-to-end tests
```

## Notes

- Rate limiting is in-process, which is right for a single instance. Behind more
  than one instance, put a shared limiter (Redis, or the platform's own) in
  front of it.
- `RESUME_API_KEYS` empty means anyone can call the API. Set keys before putting
  this on the public internet if you care about who consumes it.
